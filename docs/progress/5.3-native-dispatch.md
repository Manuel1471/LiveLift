# 5.3 — Native app-owned JavaScript events

This evidence is for maintainers verifying delivery 5.3 of experimental
LiveLift. The [spike](../native-js-dispatch-spike.md) established that
Phoenix reaches a local target before LiveLift needs any compiler support.
[ADR-0004](../decisions/ADR-0004-native-js-dispatch.md) records the scope.

## Acceptance and security

- A literal namespaced `JS.dispatch` with `bubbles: false` keeps Phoenix's
  encoded command on the bound element or a simple descendant. The compiler
  compares the output to Phoenix, including a mixed pipe with focus.
- The demo's JavaScript opens a dialog before and after an island render.
  The same binding works in the server-only counter. Opening the dialog
  leaves the LiveLift acknowledgment at its current value.
- Browser events, reserved namespaces, dynamic names or selectors, duplicate
  options, document selectors, payloads, blocking and bubbling are covered
  by source-located E053 tests. A class command and a dispatch use separate
  bindings so a synchronous app effect cannot change the target of a later
  class command during the same chain.
- The compiler calls Phoenix's encoder with the validated literals. The
  native event has a `dispatcher` element. The feature adds no supplied
  data, persisted values, state, telemetry, wire messages, HTML parsing,
  unsafe key creation, URL handling or evaluation.

## Measurement

Local verification on 2026-11-21 used LiveView 1.2.13, macOS arm64 on Apple
M4, Elixir 1.20.2, OTP 29 and Node 26.5.0. The browser matrix was Chromium
158.0.8127.18, Firefox 159.0 and WebKit 27.2.

The shared runtime remains byte-for-byte identical to `d1ea0ae` at 8,179
bytes gzip. `python3 bench/island_bundle.py` measured 55,364 bytes gzip for
the split demo entry and 63,490 for the eager entry, compared with 55,285
and 63,362 after the class increment. The demo entry includes a listener
for its dialog. A binding adds its encoded value to the counter chunk.
The reference app from `bench/phoenix_bundle.sh` stayed at 47,351 bytes
gzip with Phoenix and 55,842 with LiveLift.

`mix run bench/benchmark.exs`, `bench/phoenix_event.sh` and `npm run dom`
ran as regression checks. The event script runs 20 warm-ups and five
batches of 200 test events per variant. Batch medians were 41–44 µs for
Phoenix and 52–60 µs for Phoenix with LiveLift. The script groups variants
and measures `LiveViewTest` event handling, so it gives local server-side
context for these fixtures.

The opt-in Chromium row-edit benchmark verified focus and DOM identity
with 1,000 rows. It measured 2.3 ms median and 7.6 ms p95 with default CPU
speed over 25 samples. This run is below the sample minimum for a latency
comparison.
