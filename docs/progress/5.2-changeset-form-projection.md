# 5.2 — Changeset form projection

## Acceptance for this increment

- Native form values, field usage, default error messages, counts, and the
  order of errors agree with Ecto and Phoenix. The shared corpus runs through
  Node and Chromium, Firefox, and WebKit.
- Dynamic form options and fields omitted from `cast/3` fail at their source,
  with E052 and a server-side alternative.
- Modules that use no changeset actions omit the feature code. The existing
  runtime, event envelope, and state limits stay within their current budgets.
- The 5.2 gate remains open until a complete native form sends the same
  used-field metadata and displays the same feedback before and after a reply.

## Security review

The projection consumes existing validated event fields and creates ordinary
maps from known keys. It introduces no new input source, storage, telemetry,
or HTML insertion. The compiler bounds projected fields by the cast list
and reuses the state and parameter limits. Phoenix continues to calculate
its own authoritative form. Dynamic projections fail with E052.

## Environment and size

Local verification on 2026-11-21 used macOS arm64 on Apple M4, Elixir 1.20.2,
OTP 29, Node 26.5.0, Chromium 158.0.8127.18, Firefox 159.0, and WebKit 27.2.
The comparison baseline is `458975f`.

The shared runtime remains at 8,190 bytes gzip. The measurement minifies
`assets/js/live_lift/client_hook.js` with the demo's esbuild using
`--loader=js --format=esm --target=es2022 --minify` and compresses the
result with Python's `gzip.compress` at level 9 and `mtime=0`.
The same method gave 8,190 bytes at the baseline. The demo, which does not
yet use the Ecto projection, measured 55,290 bytes gzip for the initial
split bundle with `python3 bench/island_bundle.py`. The previous run gave
55,289 bytes using the same command.
The separate `bench/phoenix_bundle.sh` reference app measured 47,351 bytes
gzip with Phoenix and 55,856 with LiveLift, matching the previous run.
