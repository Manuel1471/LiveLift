# Phase 7 — Keep development maps out of the demo deployment

The demo has one esbuild output directory for its browser assets.
`assets.build` writes external maps there. The development watcher
can also write bundles with inline maps. On baseline `a1a8396`, running
build, digest and deploy in sequence left 28 map files, 28 compressed
copies and 13 current map entries in Phoenix's manifest.

The demo now builds the minified bundle, removes development map files
and bundles containing inline maps from the esbuild output directory,
then runs `phx.digest`. Phoenix drops digest entries whose files are
gone. The cleanup also removes compressed siblings of discarded
bundles. The original Elixir source maps generated by LiveLift remain
under the private `assets/js` directory.

```sh
cd examples/demo
mix deps.get
mix assets.setup
sh ../../test/integration/demo_source_maps.sh
```

The regression check creates both forms of maps and digests them to
exercise a dirty deployment. It checks the output files, gzip siblings
and manifest after `assets.deploy`. It also checks that the deployed
entry point, a non-bundle static file and the private compiler maps
remain present. This check runs in the CI test matrix.

On 2026-11-24 it passed on macOS 26.5.2 (Apple M4) with Elixir 1.20.2,
OTP 29, Node 26.5.0 and esbuild 0.25.4. The run also passed 18 checks
with deployed assets for view loading, fallback behavior and the script
CSP in Chromium, Firefox and WebKit:

```sh
cd bench
LIVE_LIFT_TEST_DEPLOY=1 npm run e2e -- e2e/island_loading.spec.mjs e2e/content_security_policy.spec.mjs
```
