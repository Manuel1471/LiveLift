# Phase 6 — Source audit for native timers

The [routing spike](../timer-routing-spike.md) established that a
LiveComponent shares its parent's mailbox. Audit each scheduling handler
using the same timer checks as compilation. Cover a LiveComponent update
timer and a LiveView mailbox timer with a compatible callback. Check
source-located explanations for a custom component update callback, a
timer field outside the audited client's state, an invalid delay, a
mailbox timer in a component, and a missing, guarded or shadowed
`handle_info/2` clause. Run the task against the demo and a fresh Phoenix
consumer while checking that audited source files stay untouched.

## Result

Audit now identifies both supported timer routes. It resolves simple
module aliases in declaration order and checks the selected mailbox
clause in source order. The check uses the same literal timer validators
as the regular compiler. The source-only command checks one candidate
handler at a time. Test the migrated module with Phoenix and LiveLift
in context to cover definitions generated by the app's macros and
fields introduced by other marked handlers.

In the demo, the component's `preview_timer` now reports `compatible`.
The task also reports the root LiveView's `predict` timer as compatible
and keeps its `leave` navigation event blocked. Earlier output counted
11 compatible events out of 36 and omitted the root LiveView. The updated
scope counts 17 out of 43. These totals cover different source scopes.
