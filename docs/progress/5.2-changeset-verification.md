# 5.2 — Native changeset form verification

The [projection evidence](5.2-changeset-form-projection.md) covers the
compiler and the shared corpus. This increment connects usage metadata
to browser interaction and a LiveView socket.

## Acceptance

- A change serializes only unused, visible form fields into Phoenix's
  `_unused_<field>` convention. Submission and reset follow browser
  form behavior. An opt-out continues to use the native attribute.
- An invalid form displays Ecto's ordered errors locally before the
  server receives the event. After acknowledgment, the same values,
  usage and errors remain visible. Whitespace survives in the input
  while Ecto treats it as blank. Unicode and valid submissions agree.
- Existing native form actions preserve their payloads and the core
  remains within 8 KiB gzip.

## Evidence

The [fixture](https://github.com/Manuel1471/LiveLift/blob/main/bench/changeset_live_fixture.exs) runs real Phoenix
and Ecto on loopback using test-only packages. The
[Playwright test](https://github.com/Manuel1471/LiveLift/blob/main/bench/e2e/changeset_live.spec.mjs) holds the first
browser event, checks the predicted feedback and exact params, then
forwards it and compares the authoritative state. It covers correcting
and submitting the form. The
[serializer test](https://github.com/Manuel1471/LiveLift/blob/main/bench/e2e/changeset_parity.spec.mjs) also covers
reset, hidden fields and `phx-no-unused-field`.

Run `npm run e2e -- --grep 'changeset form'` from `bench/` for the three
changeset cases in all three browsers. The real socket fixture uses Ecto
3.14.3, Phoenix Ecto 4.7.0 and LiveView 1.2.14. The Elixir/Node corpus
keeps the original pinned versions from the projection evidence.

The runtime measured 8,182 bytes gzip against 8,190 at baseline
`1df328b` using the minify and gzip command in the projection evidence.
The demo's initial split bundle measured 55,291 bytes gzip with
`python3 bench/island_bundle.py`, against 55,290 bytes at baseline.
Neither demo bundle uses the optional Ecto registry code.
The fresh reference bundle from `bench/phoenix_bundle.sh` measured
47,351 bytes gzip for Phoenix and 55,848 for LiveLift, compared with
55,856 bytes for LiveLift in the projection evidence.

The checks ran on 2026-11-21 on macOS arm64, Apple M4, with Elixir 1.20.2,
OTP 29, Node 26.5.0, Chromium 158.0.8127.18, Firefox 159.0 and WebKit 27.2.

## Security review

The serializer reads existing form controls and adds string markers to
the existing parameter map. Names and sizes still pass through the
normal serializer and event validation. Each marker counts toward the
existing limits. Generated code uses neither HTML insertion nor dynamic
evaluation. The app recomputes its own changeset and the fixture
asserts that state after acknowledgment. No libraries were added to the
LiveLift or demo application manifests.
